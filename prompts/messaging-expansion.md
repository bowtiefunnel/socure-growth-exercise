# Skill: Socure Messaging — Expansion (Upsell)

Voice standard for EXISTING-customer motions — the right side of the bowtie.
Inherits everything from `prompts/messaging-net-new.md` (evidence tiers, banned
lexicon, voice pillars, math rule) — this file only defines what CHANGES when the
audience already runs Socure. Grounding: DESIGN.md §3 (Part 2 mechanics) +
verified memo.

## The fundamental shift

| | Net-new (acquisition) | Expansion (this guide) |
|---|---|---|
| Audience | stranger who must be convinced | customer who already trusts the platform |
| Best evidence | case-study proof points | **their own usage data** — readiness signals observed in-account |
| Carrier | AE/SDR (cold) | CSM/AM (warm), growth engineer owns the signal |
| Competitive wedge | lead with counter-positioning | none — they already chose Socure; competitors appear only as displacement-defense at renewal |
| Arc | pain → mechanism → verified metric | **observed signal → what it means → mechanism → multi-product proof → low-friction next step** |

## Scope: upsell (deepen what they own)

- **Upsell** — deepen an owned pillar: KYC → +eCBSV · DocV → +Liveness ·
  higher decision volume tiers · Watchlist → +continuous monitoring.
- **Cross-sell** (introducing an UNOWNED pillar — new buyer dynamics) has its own
  standard: `prompts/messaging-cross-sell.md`. This file's existing-customer rules
  (readiness signals, guardrail, renewal honesty) are inherited there.

## Readiness signals (cite as observations, never speculation)

Only reference signals actually present in the account's data: Product-A usage
plateau · chargeback/ATO/manual-review growth on verified accounts ·
first-party or synthetic activity post-onboarding · scale threshold crossed ·
renewal inside 90 days. If the signal isn't in the data, the account isn't
ready — no play. (= the Expansion Signal Agent's rule set.)

## Multi-product proof points (verified tier — the cross-sell evidence)

- **Lili** — KYC/CIP + eCBSV, DocV + Liveness, Sigma Synthetic/Identity/Device,
  RiskScores, Watchlist → **+13% auto-approval**. Full-stack adoption, one platform.
- **Betterment** — Sigma Identity, KYC, DocV + Liveness, RiskScores, Watchlist,
  Alert List → **+30% auto-approval**.
- Frame: "accounts running multiple pillars see the platform's compounding effect" —
  then cite one of the two. Quarantined numbers stay quarantined here too.

## Voice adjustments

- **Warm, specific, relationship-aware** — reference their deployment history
  ("since KYC went live on your onboarding flow…"). Still no "we're so excited."
- **Candid about their incidents without ambulance-chasing** — Pillar 3 applies
  doubly: their fraud leakage is an engineering observation, never a scare tactic.
  DO: "Chargeback rate on verified accounts rose 3 consecutive months — that
  pattern is downstream fraud the front door can't see."
  DON'T: "Your accounts are under attack."
- **Guardrail is explicit** — every expansion play states it must not dent
  Product-A retention or NPS. Protecting the base beats the upsell.
- **Renewal-window honesty** — inside 90 days of renewal, expansion asks read as
  leverage. Name the timing, don't hide it.

## Expansion battle-card structure (when Part 2 gets a pipeline)

1. Account snapshot — products owned, tenure, usage trend (from THEIR data)
2. Readiness signal observed — the specific threshold crossed, with numbers
3. What it means — the mechanism gap (front-door verification ≠ transaction defense)
4. Product-B mechanism — which pillar closes the gap
5. Multi-product proof — Lili or Betterment
6. Guardrail — Product-A health check passes; expansion pauses if it doesn't
7. CSM opener — references the observed signal, one sentence, no pitch language
